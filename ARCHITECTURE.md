# Altara Energy Network App Architecture

## Product boundary
Altara owns the customer relationship, solar readiness calculator, customer data, vendor database, pricing logic, quote workflow, and invoices. Installers are restricted to technical verification and installation work orders; they do not see cost price, Altara profit, vendor margin, or full customer financial data.

## Stack
- Next.js App Router + TypeScript
- Tailwind CSS with shadcn/ui-style reusable components
- PostgreSQL via Prisma ORM
- NextAuth Credentials provider for private admin/installer access
- React Hook Form + Zod for customer intake validation
- PDFKit for pro-forma invoice PDF generation
- Local upload adapter under `public/uploads` for site images and vendor proofs; replaceable later with S3/R2/Cloudinary

## Route structure
- `/` public landing page and Solar Readiness Check form
- `/admin/login` secure login page
- `/admin/dashboard` pipeline dashboard
- `/admin/leads` lead pipeline list
- `/admin/leads/[id]` lead detail, load audit, photo review, site inspection, installer verification, quote/invoice/work order actions, notes/activity log
- `/admin/equipment` editable equipment database
- `/admin/vendors` editable vendor database
- `/admin/research` source register, vendor price desk, brand scoring/research notes
- `/admin/quotes` quote register
- `/admin/invoices` invoice register with pro-forma PDF links
- `/admin/maintenance` maintenance tracking
- `/installer/work-orders` installer-only work order list
- `/installer/work-orders/[id]` scoped installer view and verification checklist
- `/api/leads` public multipart intake endpoint
- `/api/invoices/[id]/pdf` pro-forma invoice PDF generator
- `/api/auth/[...nextauth]` NextAuth handler

## Database schema
The Prisma schema models the complete Altara workflow:
- customer leads, appliance loads, load audits, site inspections, photo reviews, installer verifications
- equipment items across inverter, battery, panel, cable, breaker, surge protection, mounting, earthing, combiner box, accessories
- vendors, source register, vendor price desk, research notes, equipment scoring inputs
- quotes, quote lines, pro-forma invoices, work orders, maintenance records, notes, activity logs

## Calculation logic
`src/lib/calculations/load-audit.ts` implements:
- Quantity x Wattage x Hours Used Per Day = Daily Energy Use
- total running watts, daily Wh/kWh, backup energy requirement
- suggested inverter size, battery capacity, panel array size
- system category and warning flags
- admin manual override support

## Research-driven recommendation engine
`src/lib/recommendations/brand-engine.ts` recommends budget/value/premium options from editable equipment/vendor data. It does not hardcode brand opinions; all score inputs come from database fields and research records.

## Quote and invoice governance
`src/lib/quotes/rules.ts` blocks final quote approval unless customer data is complete, load data exists, vendor prices and stock status exist, installer verification is completed or explicitly required, and an admin approves the quote. Invoices generated by the app are pro-forma only. Final invoices are intentionally gated for a future post-payment/equipment-availability check.

## Future AI photo analysis
`PhotoReview` stores human review fields plus an `aiAnalysisPlaceholder` JSON field. The UI exposes roof condition, shading risk, wiring risk, battery location risk, inverter ventilation risk, installation difficulty, additional notes, and a human-review-required toggle so a vision model can be connected without changing the workflow.
